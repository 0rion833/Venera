# Venera CLI

Venera — локальный движок контекста: он индексирует проект и отдаёт модели карту,
символы, импорты и точечные диапазоны вместо чтения файлов целиком. Работать с ним
дешевле, чем читать репозиторий, но только если сначала посмотреть на цену.

## Главное правило сессии

Когда Venera впервые упоминается в новой сессии, этот файл загружается целиком —
и первым действием нужно **измерить и показать расход**, а уже потом углубляться:

1. Если индекса ещё нет: `venera index <root>`.
2. `venera map <root> --max-tokens 600` — карта и её точная цена в токенах.
3. `venera measure <root> --rate <тариф>` — сравнение «до/после» (весь проект, топ-5).

Отчёт в начале сессии (шаблон):

```
Venera · <root> · файлов F, символов S
Расход: карта T токенов ≈ X ₽ (тариф R ₽/1M)
Без инструмента: весь проект ~M токенов ≈ Y ₽ · топ-5 ~K токенов ≈ Z ₽
```

Числа `measure` не пересчитывай на каждом сообщении: один замер на сессию, дальше
показывай только приращение (карта, outline, cat).

## Где лежит Venera

- Если `venera` есть в PATH — используй его.
- Иначе собери `cargo build --release` из корня репозитория и запускай
  `target\release\venera.exe` (Windows) или `./target/release/venera` (macOS/Linux).
- Всегда передавай явный корень проекта (`<root>`), не полагайся на текущий каталог.

## Дешёвый маршрут разбора

1. `venera index <root>` — инкрементальный индекс (parser v3: Rust, JS/TS, HTML, CSS,
   Markdown, JSON, конфиги, Python и Generic-языки).
2. `venera map <root> --max-tokens 600` — обзор файлов и символов; последняя строка
   `map N tokens…` — фактическая цена.
3. `venera search "<query>" --root <root> --limit 10` — файлы и символы по имени.
4. `venera outline <file> --root <root>` — символы файла со строками, без тела.
5. `venera deps <file> --root <root> --depth 1` — импорты и импортирующие.
6. `venera cat <file> --root <root> --from A --to B` — только нужный диапазон.
7. `venera context "<запрос>" --tokens N` — подготовленный контекст под задачу
   (если не уверен во флагах — сначала `venera context --help`).

Порядок важен: `map` → `search` → `outline` → `deps` → `cat`. Чем позже читается
исходник, тем меньше токенов уходит.

## Деньги

`₽ = токены × тариф / 1 000 000`, тариф — цена входных токенов модели в ₽ за 1M.

- 30 ₽/1M: 998 токенов ≈ 0,03 ₽; 38 640 ≈ 1,16 ₽; 11,6M ≈ 349 ₽.
- 200 ₽/1M: 998 ≈ 0,20 ₽; 38 640 ≈ 7,73 ₽; 11,6M ≈ 2 328 ₽.

В TUI `/vce` показывает отдельно `vce N tok X ₽` — это цена карты проекта, она не
начисляется в `in/out` и не считается ходом модели. `/map` — только карта,
`/index` — только индекс, `/vce` — индекс + карта одним шагом.

## Экономика и ограничения

- Не читай файлы целиком: карта, outline и cat-диапазоны дают то же понимание дешевле.
- Не переиндексируй на каждое сообщение: индекс инкрементальный, повторный запуск
  на неизменённом проекте почти бесплатен, но и смысла в нём нет.
- Карта бюджетируется: если важные файлы не влезли, подними `--max-tokens`.
- Python и Generic-языки разбираются эвристикой: символы приблизительные, вложенные
  функции и декораторы могут не попасть; неизвестные расширения — только метаданные.
- `measure` пишет индекс в `<root>\.venera\index.db`; предупреди, если проект — бэкап.

## Пример (реальный проект eventflow)

- 145 файлов, 1 417 символов, 98 импортов после индекса.
- Карта 600 токенов показала frontend и часть структуры; `search`/`outline` дали
  бэкенд (FastAPI-роуты, сервисы, схемы) без чтения файлов.
- Весь проект — 11 637 907 токенов ≈ 349 ₽; карта + один файл — 38 640 ≈ 1,16 ₽;
  экономия 99,7% против «прочитать всё» и 77,8% против топ-5.

## Когда не использовать

Обычное чтение и правка файлов без Venera, офисные документы, PDF, веб-исследования —
там работают другие навыки и инструменты.
